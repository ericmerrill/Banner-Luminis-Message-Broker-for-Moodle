# enrol_lmb Moodle 4.5–5.3 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One enrol_lmb release that installs, upgrades and runs on Moodle 4.5–5.3 / PHP 8.1–8.4, with the minimum code change.

**Architecture:** Keep the existing `lib.php`/`enrollib.php` structure. Replace the dead legacy `cron()` with three thin scheduled tasks that call existing methods, add a metadata-only privacy provider, fix only real PHP 8.1–8.4 errors/deprecations, and add moodle-plugin-ci on GitHub Actions to prove it across the whole range.

**Tech Stack:** PHP 8.1–8.4, Moodle 4.5–5.3 plugin APIs, PHPUnit (Moodle `advanced_testcase`), moodle-plugin-ci on GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-20-moodle-45-53-compat-design.md`

## Global Constraints

- `$plugin->version = 2018042503`, `$plugin->release = '4.0.0'`, `$plugin->requires = 2024100700`, `$plugin->supported = [405, 503]`, `$plugin->maturity = MATURITY_STABLE`; no `$plugin->cron`.
- PHP syntax must run on 8.1 (no 8.2+ only features: no readonly classes, no DNF types, no typed class constants).
- Minimal change: no refactoring, renaming, restyling or behaviour change beyond what a task names.
- No back-compat for Moodle < 4.5 (that lives on `Release_32`).
- Cron state is **resumed, not reset**: no upgrade step touches `prevunhideendtime`, `nextunhiderun`, `processingfolder`, `processingfile`, `xmlfiletime`.
- Tests must run on every PHPUnit version used by Moodle 4.5–5.3: `final class ... extends \advanced_testcase`, namespaced (`enrol_lmb`, `enrol_lmb\task`, `enrol_lmb\privacy`), `setUp(): void` calls `parent::setUp()`, data providers `public static`, `@covers` in class docblock.
- Every new PHP file: GPL header, `@package enrol_lmb`, `@copyright`, `@license` docblock as in existing files.
- Work targets `master`. Never push to `Release_32`.

## Review Focus

1. **File import enabled with no/missing file** (`cronxmlfile=1`, `bannerxmllocation` empty or path missing): `process_file()` calls `filemtime(null)` → PHP 8.1+ deprecation/warning every 10 minutes. Expected: task logs and returns without error. Test in Task 3.
2. **Plugin disabled** (`lmb` not in `$CFG->enrol_plugins_enabled`): old legacy cron only ran enabled enrol plugins. Expected: all three tasks do nothing. Test in Task 3.
3. **Upgrade with stale unhide window** (`prevunhideendtime` far in past): first run unhides LMB courses with startdate in `(prevunhideendtime, end of today + cronunhidedays]` — this is intended (resume). Test pins it in Task 3 so nobody "fixes" it silently.
4. **Stale `processingfolder=1`**: folder import returns immediately, forever, until cleared. Expected (resume semantics) — pinned by test in Task 3 and documented in Task 6.
5. **Single LMB message via live interface** (`process_xml_line()`, what `secure/liveimport.php` uses) on PHP 8.4: must process without deprecations. Test in Task 4.
